# 知乎版文案

**标题（任选其一）：**

1. 我给特斯拉行车记录仪写了一个时间码拼接工具：文件名里藏着的时间，一点都不会漂
2. TeslaCam 视频是 60 秒一段的碎片，我做了一个工具把它们拼回去，还带上监控级时间码

---

## 正文

特斯拉车主应该都遇到过这个问题：行车记录仪的 SavedClips 是一堆 **60 秒一段**的碎片视频，想回看一次事故全程或者发个视频，得自己拼。更麻烦的是，这些视频**导出后没有时间码**——你没法证明"这一幕发生在几点几分几秒"，画面本身也没有监控录像那种证据感。

市面上的剪辑软件（剪映、FCP）都能拼视频，但没有一个会**根据文件名自动打时间码**，逐段手动加字幕既费劲又容易错位。所以我干脆自己写了一个：**TimeCode Studio**，现在开源在 GitHub 上，个人使用免费，欢迎下载。

**GitHub 搜索：WhuEven/Tesla_TimeCodeStudio**

### 它能做什么

- **导入即出时间码**：选中文件夹（比如整个 `TeslaCam/SavedClips`）或直接拖拽，程序从文件名（`2026-10-29_19-03-40-front.mp4`）解析出拍摄起始时间，右下角生成随播放实时跳动的 `年-月-日 时:分:秒`，标准监控 OSD 风格
- **监控专用点阵字体**：内置一套 5×7 点阵字体（程序用 fontTools 现场生成，无任何字体版权问题），白字黑描边，也支持半透明底板、可调字号、副行文本
- **自动读取地点元数据**：特斯拉文件里带 GPS 地点（比如"杭州 丹枫路"），导入后自动填进 OSD 第二行，可改可关
- **拼接 + 截取**：多片段按时间排序拼成连续时间轴，每段可设入点/出点（双击列表改，或打开对话框拖滑块看预览帧）
- **码率可选 + 体积预估**：预设 12/8/6/4/2.5 Mbps，导出前**实时预估文件大小**，实测偏差在 ±10% 以内
- macOS / Windows 双平台，图形界面，导出有进度条和日志

### 时间码为什么不会漂移（技术上比较有意思的部分）

TeslaCam 有个坑：每段视频约 60 秒，但相邻段的文件名时间戳相差约 **61 秒**——录制之间有缝隙。如果按"累计播放时长"推算时间，每拼一段就多漂 1 秒，十个片段下来错半分钟。

我的做法是**完全不累计**，每个片段的时间码直接锚定在它自己文件名的时间戳上：

```
显示时间 = 片段文件名时间戳 + 段内偏移（含截取入点）
```

缝隙处时间码如实跳 1 秒，跨片段、跨截取都零漂移。实现上是一条覆盖整个时间轴的 ASS 字幕交给 libass 渲染，位置、字号按输出分辨率等比缩放。

实测：3 段前视拼接（中间段截取 10–30 秒），抽 t=5s / 62s / 100s 三帧核对，时间码分别为 19:03:45 / 19:04:53 / 19:06:01，与理论值**逐秒一致**。139 秒的 720p/2Mbps 导出耗时 26 秒。

### 使用

```bash
git clone https://github.com/WhuEven/Tesla_TimeCodeStudio.git
cd Tesla_TimeCodeStudio
pip install -r requirements.txt
python main.py
```

macOS 双击 `run.command`，Windows 双击 `run.bat`。ffmpeg 不用手动装——找不到系统 ffmpeg 时会自动用 pip 附带的静态版本。

### 几点说明

- 兼容其他按时间命名的监控视频（不只特斯拉）；文件名被改过的片段会自动用相邻片段的时间推算补齐
- 6 路视角（前/后/左右侧/左右柱）分辨率不同，建议导出时用"启用视角"切到单一路；混剪会等比缩放加黑边
